### Contract Architecture & Non-Standard Return Quirk
- FerryHTLC ported to Tron TVM in packages/htlc-tron/contracts/FerryHTLC.sol.
- The permit function lockWithIntent was dropped (decision D-A3-006) because Tron TRC-20 tokens do not implement EIP-2612 permit. Swaps proceed via TRC-20 approve followed by lock.
- Tron's Tether USDT contract implementation does not return a boolean value on transfer and transferFrom (returns void / zero bytes). Standard ERC20 interfaces expecting a boolean return value will revert upon decoding return data.
- OpenZeppelin SafeERC20 was integrated to wrap all token transfers, inspecting return data length and treating empty return data as success.
- A test mock with the exact USDT non-standard return quirk (MockNoReturnTRC20) was authored and evaluated. All lock, claim, and refund transactions with void-return tokens succeed without reverting.

### TVM Opcode Divergence
- TronBox bundles tron-solc 0.8.31, which generates bytecode for the Tron Virtual Machine (TVM).
- The compiler injects custom opcodes 0xd2 and 0xd3 into the constructor preamble to handle TRC-10 token transfers and tags CBOR metadata with tron.
- Standard Ethereum EVM execution clients (Anvil, Geth, Hardhat) do not support opcodes 0xd2/0xd3 and revert with OpcodeNotFound.
- Local testing of contract logic, error reverts, and safe-transfer quirks is compiled via standard Solc (Foundry), while deployments to Nile testnet utilize the tron-solc artifacts generated by TronBox.
